# ESP32-S3-DevKitC-1-N32R16V — board reference (host board, Phase 2+)

Authoritative chip/build specifics for the DevKitC we use as the USB **host**.
Cross-checked against a working project for the *same board* on this machine:
`C:\Users\tav08\Documents\GitHub\ESP32-S3 Mega Scanner` (its `firmware/boards/
esp32s3_n32r16v.json`, `platformio.ini`, and `README.md`).

## The module

- **ESP32-S3-WROOM-2-N32R16V** on a DevKitC-1 v1.1 carrier.
- **32 MB Octal (OPI) flash**, **16 MB Octal (OPI) PSRAM**, **1.8 V** SPI.
  - "Octal/OPI" is the load-bearing fact: the flash **must** be read in OPI mode
    or the chip boot-loops. `FlashMode=qio`/`dio` will NOT boot this board.
- Mega Scanner declares it in **"N16R8 mode"** — flash as **16 MB**, partitions
  `*_16MB.csv`. We do the same (our sketch is tiny; 16 MB is plenty and avoids
  the flakier 32 MB declaration). `f_flash = 80 MHz`.
- WS2812 RGB LED on **GPIO38** (v1.1; v1.0 used GPIO48). Not driven by us.

## Two USB ports (don't mix them up)

| Silkscreen | Behind it | We use it for |
|---|---|---|
| **`UART`** | On-board CP210x bridge. DTR/RTS wired to `EN`/`IO0` → **auto-reset** into download mode. ROM bootloader prints here (UART0, hardwired). | **Everything: flashing + serial console.** This is COM7 on this machine. |
| **`USB`** | Native USB on the chip (GPIO19/20). | **Left UNPLUGGED** — we need GPIO19/20 free to wire the dongle for USB-host. |

`BOOT` (GPIO0) and `RST` buttons sit just above the ports.

## Our build config (arduino-cli)

We diverge from Mega Scanner in exactly one knob: **USB Mode**. They use
*Hardware CDC and JTAG* (they don't do USB-host); we need the **USB-OTG**
controller free for `EspUsbHost`, so `USBMode=default`. Everything else mirrors
their proven memory config.

```
--fqbn "esp32:esp32:esp32s3:USBMode=default,CDCOnBoot=default,FlashMode=opi,FlashSize=16M,PSRAM=disabled"
```

| Flag | Value | Why |
|---|---|---|
| `USBMode` | `default` (USB-OTG/TinyUSB) | Frees the OTG controller + PHY for the EspUsbHost **host** driver. (Mega Scanner uses `hwcdc`; that's device-side only and would hold the PHY.) |
| `CDCOnBoot` | `default` (disabled) | `Serial` → UART0 → CP210x → **COM7**. Survives the OTG PHY being claimed for host. (Phase-1 proven on the OTG board too.) |
| `FlashMode` | `opi` | **Mandatory** for the WROOM-2 Octal flash. Wrong value = boot loop. |
| `FlashSize` | `16M` | "N16R8 mode," matches Mega Scanner. |
| `PSRAM` | `disabled` | Our firmware never touches PSRAM, so skip the OPI-PSRAM init entirely (one less boot-time failure mode). Set `PSRAM=opi` only if a future sketch allocates from `MALLOC_CAP_SPIRAM`. |

> Arduino IDE equivalents (if ever needed): USB CDC On Boot **Disabled**, USB Mode
> **USB-OTG (TinyUSB)**, Flash Mode **OPI 80MHz**, Flash Size **16MB**, PSRAM
> **Disabled**. (Mega Scanner's README documents the *device-CDC* recipe — CDC On
> Boot Enabled + HW CDC/JTAG — which is the opposite of what host mode wants.)

## Flashing gotchas (from the Mega Scanner README, verified board)

- Flash + monitor on the **`UART`** port (COM7). Auto-reset normally fires.
- **`Failed to connect to ESP32-S3`** during upload = auto-reset didn't fire:
  hold **`BOOT`**, tap **`RST`**, release **`BOOT`**, retry the upload. After it
  finishes, press **`RST`** once to run the new app.
- Bootloader text always prints on `UART`/UART0 regardless of CDC mode.

## Host wiring (USB-A female breakout → DevKitC headers)

Native USB host: dongle's 4 USB lines go to the headers (NOT the `USB` port).

| USB-A | Wire | DevKitC pin |
|---|---|---|
| 5V (VBUS) | red | **5V** (J1-21) — powers the dongle |
| D− | white | **GPIO19** (J3-20) |
| D+ | green | **GPIO20** (J3-19) |
| GND | black | **GND** (J3-21) |

Keep D+/D− short and equal length. UART link to the Pico: **GPIO47 → Pico GP1**,
GPIO48 ← Pico GP0 (Phase 3), GND↔GND.
